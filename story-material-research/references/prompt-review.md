# 提示词审查机制

**Skill:** `story-research-prompt`
**Phase:** 3 — 生成后审查
**Last Updated:** 2026-07-27

---

## 1. 审查工作流

```
提示词生成完成
        ↓
Step 1: 逐项检查（8 项检查单）
        ↓
    ┌─── 全部通过 ───┐
    │                 │
    ↓                 ↓
输出最终提示词    进入 Step 2
                      ↓
            Step 2: 定位失败项
                      ↓
            Step 3: 修复提示词
                      ↓
            Step 4: 重新审查
                      ↓
                 通过 → 输出
                 未通过 → 再次修复（最多 3 轮）
                               ↓
                          3 轮后仍失败 → 返回"无法生成"报告
```

---

## 2. 8 项审查检查单

### 检查项 1: 研究对象是否清楚

| 检查点 | 通过标准 | 失败表现 |
|--------|---------|---------|
| 作品标题是否明确 | 提示词包含完整作品名 | 只有模糊描述（如"一部悬疑小说"） |
| 是否有消歧说明 | 同名作品有版本/年份区分 | 无消歧说明，可能混淆 |
| 作者/导演是否标注 | 提示词包含创作者信息 | 未标注创作者 |
| 研究范围是否界定 | 有明确的章节/片段/季数范围 | 全作品研究但未说明 |

**失败修复：**
- 补充缺失的基本信息
- 添加消歧说明
- 明确研究范围

---

### 检查项 2: 问题是否可被检索验证

| 检查点 | 通过标准 | 失败表现 |
|--------|---------|---------|
| 问题是否具体 | 每个问题有明确的研究对象 | 问题过于宏大（如"为什么成功"） |
| 问题是否可搜索 | 能通过关键词检索到答案 | 问题无法通过搜索验证（如"作者潜意识"） |
| 问题是否有层次 | 问题间有逻辑递进 | 问题之间相互独立、无关联 |
| 问题数量是否合理 | 5-20 个问题 | 问题过多（>25）或过少（<3） |

**失败修复：**
- 将宏大问题拆成具体子问题
- 将不可验证的问题改为可搜索验证的形式
- 调整问题数量到合理范围

---

### 检查项 3: 是否要求事实与观点分离

| 检查点 | 通过标准 | 失败表现 |
|--------|---------|---------|
| 是否有分层标记规则 | 提示词包含 5 层标记要求 | 无分层标记规则 |
| 是否明确禁止混淆 | 提示词禁止把评论写成事实 | 无禁止混淆的表述 |
| 是否有引用规范 | 提示词要求注明来源 | 无引用规范 |

**失败修复：**
- 补充 5 层信息标记规则（事实/官方/评论/推断/待验证）
- 补充禁止混淆的明确表述
- 补充引用规范

---

### 检查项 4: 是否规定来源优先级

| 检查点 | 通过标准 | 失败表现 |
|--------|---------|---------|
| 是否有来源优先级链 | 提示词包含 6 级优先级 | 无来源优先级或只有 1-2 级 |
| 是否有禁止来源 | 提示词包含 Level X 清单 | 无禁止来源说明 |
| 是否有来源记录要求 | 提示词要求记录来源类型、权威性 | 无来源记录要求 |
| 是否有冲突处理 | 提示词要求标记来源冲突 | 无冲突处理要求 |

**失败修复：**
- 补充完整的 6 级来源优先级
- 补充禁止来源清单
- 补充来源记录要求和冲突处理规则

---

### 检查项 5: 是否有明确输出格式

| 检查点 | 通过标准 | 失败表现 |
|--------|---------|---------|
| 是否有固定章节结构 | 提示词包含 14 章结构 | 无固定结构或章节不全 |
| 每章是否有明确要求 | 每章有具体的研究要求 | 章节要求模糊 |
| 是否有证据索引要求 | 提示词要求输出证据索引 | 无证据索引要求 |
| 是否有缺口披露要求 | 提示词要求列出资料缺口 | 无缺口披露要求 |

**失败修复：**
- 补充完整的 14 章输出结构
- 为每章补充具体的研究要求
- 补充证据索引和缺口披露要求

---

### 检查项 6: 是否会诱导工具大篇幅复述作品

| 检查点 | 通过标准 | 失败表现 |
|--------|---------|---------|
| 是否要求"概述"而非"全文" | 提示词要求概述/总结 | 提示词要求"详细复述每一章" |
| 是否有引用定位要求 | 提示词要求定位到章节/集数 | 允许模糊引用（如"书中提到"） |
| 是否有篇幅控制 | 提示词对输出篇幅有指导 | 无篇幅控制，可能诱导大段引用 |
| 是否要求提炼机制 | 提示词要求提炼"机制"而非复述情节 | 仅要求描述情节 |

**失败修复：**
- 将"复述"改为"概述"或"总结"
- 添加引用定位要求（章节/集数/场次）
- 添加篇幅控制指导
- 将"描述情节"改为"提炼机制"

---

### 检查项 7: 是否包含创作迁移目标

| 检查点 | 通过标准 | 失败表现 |
|--------|---------|---------|
| 是否有可迁移方法要求 | 提示词要求输出"可迁移的创作方法" | 无创作迁移要求 |
| 是否有不可照搬要求 | 提示词要求输出"不可直接照搬的特征" | 无不可照搬说明 |
| 是否有适用条件要求 | 提示词要求说明方法适用条件 | 无适用条件说明 |

**失败修复：**
- 补充"可迁移的创作方法"要求
- 补充"不可直接照搬的特征"要求
- 补充适用条件说明要求

---

### 检查项 8: 是否要求披露资料缺口

| 检查点 | 通过标准 | 失败表现 |
|--------|---------|---------|
| 是否有"无法确认"要求 | 提示词要求找不到证据时写"无法确认" | 允许推测代替证据 |
| 是否有缺口章节 | 提示词包含"资料缺口与不确定结论"章节 | 无缺口披露章节 |
| 是否有不确定结论标记 | 提示词要求标记不确定结论 | 无不确定性标记 |
| 是否有冲突披露要求 | 提示词要求披露来源冲突 | 无冲突披露要求 |

**失败修复：**
- 补充"无法确认"规则
- 补充"资料缺口与不确定结论"章节
- 补充不确定结论标记要求
- 补充冲突披露要求

## 3. 审查失败处理规则

### 3.1 失败等级

| 等级 | 条件 | 处理 |
|------|------|------|
| A 级（阻断） | 检查项 1/3/4/5 失败 | 必须修复，无法输出 |
| B 级（重要） | 检查项 2/6/7/8 失败 | 必须修复，影响质量 |
| C 级（轻微） | 表述不够精炼 | 建议修复，不影响功能 |

### 3.2 修复策略

| 失败项 | 修复方法 |
|--------|---------|
| 研究对象不清楚 | 从用户输入提取信息，补充到提示词 |
| 问题不可验证 | 重写问题，使用"如何"、"哪些"、"什么机制"开头 |
| 事实观点分离缺失 | 直接插入模块 7 的证据规则 |
| 来源优先级缺失 | 直接插入模块 6 的来源策略 |
| 输出格式缺失 | 直接插入模块 9 的输出结构 |
| 诱导复述 | 修改措辞，添加"概述"要求 |
| 创作迁移缺失 | 补充模块 11 相关要求 |
| 缺口披露缺失 | 补充"无法确认"规则和缺口章节 |

### 3.3 迭代限制

- 最多 3 轮修复
- 3 轮后仍有 A 级失败 → 返回"无法生成"报告
- 3 轮后仅有 C 级失败 → 可以输出（标记为"部分达标"）

## 5. 审查迭代机制

### 5.1 迭代流程

```
第一轮审查
    ├─ 全部通过 → 输出
    └─ 有失败项 → 修复 → 第二轮审查
                            ├─ 全部通过 → 输出
                            └─ 有失败项 → 修复 → 第三轮审查
                                                    ├─ 全部通过 → 输出
                                                    └─ A 级失败 → 返回"无法生成"
```

### 5.2 迭代日志

每次迭代记录：

| 字段 | 说明 |
|------|------|
| `iteration` | 第几轮迭代（1/2/3） |
| `checks` | 各项检查结果 |
| `fixes_applied` | 本次修复的内容 |
| `remaining_issues` | 仍存在的问题 |

### 5.3 迭代上限

- 最大迭代次数：3 次
- 每次迭代必须解决至少 1 个 A 级失败
- 连续 2 次迭代无改善 → 提前终止

## 6. 审查自动化接口

### 6.1 审查函数签名

```python
def review_prompt(prompt: str, research_mode: str) -> ReviewResult:
    """
    审查生成的 Deep Research 提示词
    
    参数:
        prompt: 生成的提示词文本
        research_mode: 研究模式（comprehensive/structure/character/...）
    
    返回:
        ReviewResult: 审查结果
    """
    checks = {
        "subject_clarity": check_subject_clarity(prompt),
        "question_verifiability": check_question_verifiability(prompt),
        "fact_opinion_separation": check_fact_opinion_separation(prompt),
        "source_priority": check_source_priority(prompt),
        "output_structure": check_output_structure(prompt),
        "anti_recitation": check_anti_recitation(prompt),
        "creative_transfer": check_creative_transfer(prompt),
        "gap_disclosure": check_gap_disclosure(prompt)
    }
    
    return evaluate_review(checks)
```

### 6.2 审查结果结构

```python
@dataclass
class ReviewResult:
    status: Literal["passed", "passed_with_fixes", "failed"]
    checks: dict[str, Literal["pass", "fail", "warning"]]
    issues: list[ReviewIssue]
    fixes_applied: list[FixRecord]
    recommendation: Literal["output", "fix_and_retry", "return_to_user"]

@dataclass
class ReviewIssue:
    check: str
    issue: str
    severity: Literal["A", "B", "C"]
    suggestion: str
```
