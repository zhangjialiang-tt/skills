# AI 短剧试播集前期生产包

把一个故事基线变成一套**可直接投入 AI 图片/视频生成与剪辑的离线前期生产资料包**。本 skill 产出资料本身，不实际生成图片/视频/音频。

> 出处：源流程为《明天的来电》试播集生产包（2026-10-29，75s/14 镜/六阶段交付并通过四视角审查），已去除项目专属内容；下文出现的片名、人物、门链等仅为示例标注。

## 完成判据（达到即停，不扩展）

1. 一份可直接阅读的正式剧本。
2. 一套时长完全闭合的分镜（`verify_timeline.py <shot_list.csv> --total <目标秒数>` 返回 0）。
3. 一套人物与场景视觉合同（短项目可裁剪，见下方"产物裁剪"）。
4. 每镜均有可执行的生成提示词（中英双语）。
5. 每镜都有替代实现方案段落；其中高风险镜的替代必须分层（零生成成本方案排第一）。
6. 声音与剪辑时间线可与分镜对齐。
7. 一份 15–20 秒试生成测试方案。
8. README 说明生产顺序、资源需求、待验证事项。

追求"可实际制作"，不追求文档数量；不扩展第二集或完整剧集。

**产物裁剪（短项目）**：成片 ≤30s 或镜头 ≤8 时，可按下述方式减少**文件数量**，但不减少**检查项**（与上文判据字面冲突时以本节为准，裁剪项写进 README 与最终汇报）：

- 四份审查可合并为一份 `review.md`，四个视角各一节，问题编号与 P0/P1/P2 分级照旧；
- 视觉合同至少保留人物 + 风格两份；纯单场景、无空间调度需求时可省 `location_bible.md`（在 README 登记原因）；
- `pilot_test_plan` 试生成段可压到 2 镜，验收项不得删。

## 输入参数

| 参数 | 默认 | 说明 |
|---|---|---|
| 故事基线 | **必需** | 题材、人物、必须保留的情节点 |
| 总时长 | 60–90s，目标 75s | 所有时间码的原点；用户指定值优先 |
| 画幅 | 9:16（1080×1920） | |
| 镜头数 | 12–16 | 用户可指定；每镜约 3–10s。**镜头数×单镜时长与总时长冲突时，以总时长闭合为准**：平均单镜 = 总时长 ÷ 镜头数，落在 3–10s 即合理 |
| 人物数 | 1 | 每多一个稳定出现的角色，一致性风险和成本显著上升 |
| 提示词语言 | 中文 + 英文 | |
| 输出目录 | `<workspace>/<项目名>/pilot-01/` | 目录已存在时**不覆盖**用户原有内容：同名文件冲突则递增为 `pilot-02/`，改目录前先问一次 |
| 成本约束 | 无 | 用户说"动态生成越少越好"时，把更多镜头设计为静帧后期 |

缺少故事基线时先问一次——它决定全部下游产出。其余参数有合理默认，不要用问题阻塞任务。

## 硬边界

- 不调用付费 API，不生成图片/视频/音频，除非用户明确要求且已确认成本。
- 不宣称任何未经官方文档验证的模型能力、参数档位或价格；一律标注"待验证"（时长档位、参考图机制、首尾帧控制等都属此类）。
- 屏幕文字、字幕、片名、UI 一律后期制作，不依赖模型生成文字——生成屏幕出现乱码是必然事件，只能靠"生成纯亮屏/黑屏 + 后期叠加"规避。
- 每阶段产出后立即验证，验证不过不进下一阶段；不为消耗 token 重复推演，评审一次性给出结论，不循环重写。

## 与相邻 skill 的边界

本 skill 的交付物是**离线资料**，全程不产出任何图片/视频/音频文件。判断归属看"用户要什么结果"，不看"是不是视频题材"：

- 要"能直接播放的成片 MP4"、画面由 HTML/CSS/代码动画构成 → 用 `hyperframes-video`，不走本 skill。
- 两者都要（先要生产资料、再要成片）：先跑本 skill 出 `pilot-01/`，把 `04_prompts/` 与 `05_audio_editing/` 交给下游工序，不要在本 skill 内渲染。
- 用户已有生产资料、只问某个环节（例如"帮我改一条提示词"）→ 只做该环节，不重启六阶段。

## 流程总览

| 阶段 | 产出 | 验证门（不过不进下一阶段） |
|---|---|---|
| A 剧本 | script_review.md、screenplay_final.md | 评审矩阵有结论；版本一次性选定 |
| B 分镜 | storyboard.md、shot_list.csv | `verify_timeline.py --total <目标秒数>` 返回 0（行内一致 + 区间连续 + 总时长吻合） |
| C 视觉合同 | 三份视觉合同 | 三分清单完整；token 可逐字引用 |
| D 提示词 | 逐镜提示词 + manifest | 每镜段落齐全；manifest↔文件互检通过 |
| E 声音剪辑 | audio/editing/pilot_test 三份 | 时间码与 shot_list 逐条对齐 |
| F 审查 | 四份审查 + revision_log | 机器校验打底；P0/P1 修复后复验通过 |
| 收尾 | README、progress.md | 完成判据 1–8 逐条打勾 |

各阶段怎么做好，读对应细则（按需加载，不要一次全读）：

- **写分镜和提示词前必读** `references/pitfalls.md`——12 条实战坑，每条都有源案例，踩中任何一条都可能毁掉成片一致性。
- A+B 剧本与分镜 → `references/stage-play.md`（多版本竞争法、评审矩阵、分镜 13 字段、台词时长数学）
- C 视觉合同 → `references/stage-visual.md`（token 契约写法、三分法、防漂移规则）
- D 提示词 → `references/stage-prompts.md`（每镜 10 段结构、约束清单、manifest 字段）
- E+F 声音剪辑与审查 → `references/stage-audio-review.md`（时间线对齐、四视角证据制审查、修订轮次）

## 核心方法论（六阶段背后的三条主线）

**1. 竞争再收敛**：剧本阶段必须先写 3 个差异明确的版本再评审选优（见 stage-play.md）。直接写"最终版"会错过更优结构；但评审必须一次性给出结论，禁止无限循环重写。

**2. 机器校验打底，人工审查收口**：凡是能脚本验证的（时长闭合、文件互检、台词余量、旧引用残留）一律写脚本跑，审查文档引用脚本输出作为证据；脚本查不出的问题（轴线、逻辑、情绪节奏）才靠四视角人工审查。审查发现的问题按 P0/P1/P2 分级，只修高优先级，最多两轮实质修订——修 P2 会陷入打磨循环。

**3. 一切以"生成会失败"为默认假设**：每个镜头都必须有"生成失败时的替代方案"（通常是静帧后期，成本近零）；每个跨镜必须一致的元素（人物、道具、光源）都必须有契约条目和参考图计划。整个生产包的价值一半在主方案，一半在兜底方案。

## 工具

### scripts/verify_timeline.py

分镜时长闭合校验，阶段 B 和阶段 F 复验都用它。**`<skill>` = 本 SKILL.md 所在目录**；你的当前目录一般是输出目录，裸写 `scripts/...` 会找不到文件：

```bash
python <skill>/scripts/verify_timeline.py shot_list.csv --total 75.0     # 门禁用法：必带 --total
python <skill>/scripts/verify_timeline.py shot_list.csv --start-col s --end-col e --duration-col dur  # 换列名
```

**门禁必须带 `--total <目标秒数>`。** 不带时脚本只校验"每行 end−start == duration"与"区间首尾相接"，
**总时长与用户要求不符也会返回 0**（此时脚本打印 WARNING，门禁不得依赖警告放行）——实测：目标 30s、实际 34s 的 shot_list 不带 `--total` 判定通过。
目标值取用户指定秒数；用户未指定则取默认 75.0。

退出码 0=通过，1=失败（逐行打印原因），2=用法或文件错误。把它复制到项目 `06_review/` 下作为 `verify_consistency.py` 的基础，再按项目追加互检项（manifest 文件存在性、契约词抽查等）。

## 汇报方式

完成后如实汇报：各阶段产出位置、实际执行的验证及深度（脚本校验了什么、人工推演了什么）、待验证清单。**未实际生成/测试视频时，禁用"已生成""已测试"等表述**。
