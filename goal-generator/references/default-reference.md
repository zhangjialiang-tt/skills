# 默认策略参考（Default-First）

## 核心原则

低风险、低成本、可逆的不确定性，由 Skill 选择保守默认值，不拦用户填表。

只有当决策会实质改变以下内容时才追问：
- 产品方向
- 完成范围
- 成本
- 风险
- 所有权
- 数据安全
- 外部权限
- 不可逆操作
- 验收标准

## 任务类型 → 默认策略映射

| 任务类型 | 默认策略 | 理由 |
|---------|---------|------|
| 新产品原型 | 本地最小闭环，先做核心流程 | 最快验证核心体验，避免账号/后端/发布拖慢 |
| 存量工程 | 先读取已有文档、脚本、测试和约束 | 避免破坏现有约定和隐藏约束 |
| Bug 调试 | 先复现和建立证据基线 | 避免基于错误假设的修复 |
| 性能优化 | 先建立当前性能基准 | 避免无基准的虚假优化 |
| 陌生专业领域 | discovery-first | 避免编造领域规则 |
| 发布/生产数据/凭证/付款/破坏性操作 | 不得默认执行，必须暂停 | 高风险操作需人工确认 |

## 默认选择理由模板

```
默认选择理由：[一句话说明为什么这些默认选项成本最低、风险最稳或最能验证核心价值]。
```

## 编号选择题模板

只在信息不足且决策会影响方向时使用：

```
可选调整
1. [决策维度]：A [推荐默认] / B [替代] / C [高成本选项]
2. [决策维度]：A [推荐默认] / B [替代] / C [高成本选项]
3. [决策维度]：A [推荐默认] / B [替代] / C [高成本选项]

你可以直接回复：按默认，或回复类似 1B 2A 3C。
```

## 不应默认的场景

- 涉及生产数据访问
- 涉及凭证、密钥、密码
- 涉及付款或财务操作
- 涉及破坏性删除或不可逆操作
- 涉及法律/医疗/金融判断
- 涉及版权素材或官方授权
- 涉及所有权或产品方向不清
- 涉及外部部署或发布

这些情况必须在 Goal 中写入 Pause 条件，且不得默认继续。

## 示例：默认策略的正确使用

**场景：** 用户说"帮我做个待办事项 App"

**正确做法：**
1. 选择 Standard Goal Profile
2. 默认本地 MVP + 核心流程
3. 给出默认选择理由
4. 提供编号选择题

**错误做法：**
1. 直接问用户"你要本地还是云端？单机还是联机？要不要登录？"
2. 把所有任务都默认成"创建本地 MVP"（例如用户其实是要修一个现有项目的 bug）
3. 对 Bug 调试任务也默认"先做 MVP"
