# Discovery-First 策略参考

## 适用场景

任务涉及陌生、专业或高风险领域，且 Skill 不具备该领域专业知识时：

- 医疗、健康、诊断
- 金融、合规、法律
- 特定行业的专业数据格式
- 用户自定义的协议或规范
- 工作区内有权威文档但 Skill 尚未读取

## 核心原则

1. **不得编造领域规则** — 不假装懂专业知识
2. **先读取权威信息** — 工作区文档、规范、样例、脚本、测试
3. **列出工作假设** — 明确标注哪些是假设，哪些是证据
4. **证据不足时暂停** — 不得擅自固化领域结论
5. **发现后仍要交付** — 除非任务只是调查，否则发现阶段后应完成最小可验证目标

## Discovery-First Goal 模板

```text
/goal 创建一个安全的 [任务领域] 第一版，先读取工作区内的 [权威信息来源]，再实现最小可验证 [核心流程]。
验证：识别并读取 [项目文档/样例数据/现有脚本/官方参考资料]；运行最小相关检查；用样例数据完整走通一次 [核心流程]，并以日志、截图或导出文件作为证据。
约束：不编造 [领域规则/合规声明/数据语义/用户承诺]；不处理 [生产数据/真实用户数据]；不改变未理解的数据格式。
边界：只修改第一版 [核心流程] 直接需要的 [文件/模块]；不触碰 [生产配置/凭证/无关模块]。
迭代策略：先完成发现阶段并列出工作假设，再实现一个聚焦切片；每次失败后基于日志或文档调整，最多做 3 轮聚焦改进。
完成条件：样例数据下的最小 [核心流程] 有运行证据证明可用，检查通过或明确说明缺少配置，未解决的领域问题被列出。
暂停条件：需要 [领域专业判断/合规审批/真实数据/外部付费服务/生产部署/破坏性操作] 时暂停。
```

## 示例：医疗影像标注工具

**输入：** "帮我创建一个医疗影像标注工具"

**输出：**

```text
/goal 创建一个安全的医疗影像标注工具第一版，先读取工作区内的项目文档、样例数据说明和可用脚本，再实现最小可验证标注流程。
验证：识别并读取项目文档、样例数据说明、现有脚本或官方参考资料；运行最小相关检查；用样例数据完整走通一次导入、标注、保存、重新打开流程，并以日志、截图或导出文件作为证据。
约束：不编造医学结论、合规声明、数据语义或诊断用途；不处理生产患者数据；不改变未理解的数据格式。
边界：只修改第一版标注流程直接需要的界面、状态和样例数据处理文件；不触碰生产配置、凭证或无关模块。
迭代策略：先完成发现阶段并列出工作假设，再实现一个聚焦切片；每次失败后基于日志或文档调整，最多做 3 轮聚焦改进。
完成条件：样例数据下的最小标注流程有运行证据证明可用，检查通过或明确说明缺少配置，未解决的领域问题被列出。
暂停条件：需要医疗判断、合规审批、真实患者数据、外部付费服务、生产部署或破坏性数据迁移时暂停。
```

## 示例：自定义协议解析器

**输入：** "帮我解析这个自定义的二进制日志格式"

**输出：**

```text
/goal 创建一个安全的自定义二进制日志解析器第一版，先读取工作区内的协议规范文档、样例日志文件和现有解析脚本，再实现最小可验证解析流程。
验证：识别并读取协议规范文档、样例日志、现有解析代码或官方参考资料；运行最小相关检查；用样例日志完整走通一次解析、验证、输出流程，并以日志、截图或导出文件作为证据。
约束：不编造协议字段含义、数据语义或用途；不处理生产日志数据；不改变未理解的数据格式。
边界：只修改第一版解析流程直接需要的解析器、验证器和样例数据处理文件；不触碰生产配置、凭证或无关模块。
迭代策略：先完成发现阶段并列出工作假设（字段含义、字节序、边界条件），再实现一个聚焦切片；每次失败后基于日志或文档调整，最多做 3 轮聚焦改进。
完成条件：样例日志下的最小解析流程有运行证据证明可用，检查通过或明确说明缺少配置，未解决的协议问题被列出。
暂停条件：需要协议规范权威解释、生产日志访问、外部付费服务或破坏性数据迁移时暂停。
```

## 不应使用 Discovery-First 的场景

- 任务领域是通用编程（Web 开发、CLI 工具、常规后端）
- 用户已经提供了完整的规格和约束
- 工作区内没有任何权威文档可供发现
- 任务本身就是快速原型，不需要领域准确性

在这些情况下，使用 Default-First 策略即可。
