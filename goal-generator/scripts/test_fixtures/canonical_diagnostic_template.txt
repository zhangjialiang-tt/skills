/goal

【期望结果】
消除订单导出任务在大数据量下卡死的问题，使导出能够完整结束并产生正确文件，同时保持现有导出接口不变。

【当前事实】
- 导出任务偶发卡死在约 50% 进度
- 日志最后停在 writing csv 阶段
- 测试入口：pytest tests/test_export.py
- 数据库：PostgreSQL 14，后端 Python

【待验证假设】
- 文件锁或长事务可能导致卡死（待验证）
- 用户建议加超时（待验证方案）
- 其他可能：游标未分批、内存累积、外部存储响应慢

【验收证据】
1. pytest tests/test_export.py -v 全部 PASS（回归验证）
2. 大数据量导出任务能够完整结束并生成正确 CSV 文件（复现场景验证）
3. 导出接口请求/响应格式修改前后一致（接口一致性检查）

【必须保持】
- 不改变现有导出 API 的请求/响应格式
- 不降低现有测试覆盖率
- 不通过跳过大数据量用例或截断导出来虚假达成完成
- 不屏蔽错误日志来虚假达标

【工作边界】
允许修改：
- services/export/ 目录内的业务逻辑
- tests/test_export.py 中的测试用例

只读参考：
- 数据库 schema 定义

禁止修改：
- 生产数据库配置
- 第三方存储 SDK 源码

【迭代策略】
- 先复现：在测试环境构造大数据量导出，确认至少复现 1 次卡死；
- 建立进度与日志基线；
- 优先执行能区分候选根因的最小实验；
- 一次只引入一个可归因变量；
- 修改后先运行最小相关测试，再运行完整回归。

【阻塞与停止】
仅在所有验收证据满足时判定完成。
若测试环境无法构造大数据量、缺少生产日志访问权限或必须修改数据库 schema，
停止修改并报告：
- 已尝试路径；
- 获得的证据；
- 当前判断及置信度；
- 未解决风险；
- 解除阻塞所需的最小输入。
