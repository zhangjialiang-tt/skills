# 内容方法论：脚本 · 分镜 · 视觉系统

> 出处：hyperframes-agent-video 项目实战（2026-10-29/30），方法通用，数值为标注示例。

## 1. 脚本：语速预算表

旁白节奏决定成片质感，用预算表约束每一句：

| 场景 | 时长 | 旁白字数 | 语速（字/秒） | 判定 |
|---|---|---|---|---|
| S01 | 7s | 26 | 3.7 | 留悬念，可接受 |

- 中文舒适区 4.0–4.5 字/秒；单句超 4.8 字/秒即为全片最快句，要在分镜里给它留提前量。
- 前置逻辑：**先定场景时长 → 按预算算每句字数上限 → 写文案**，反过来必然超时。
- 英文术语（产品名）按 2 字/词折算占时；混读句实测校准。

## 2. 事实核查表（脚本不可少的一部分）

每条产品表述一行：表述 → 依据出处（官方文档/源码/本片制作事实）→ 结论。
规则分两类，不混为一谈：

- **用户明确声明为虚构/演示用的设定**（虚构产品名、官网、卖点）：允许保留，
  表中标注"虚构"，并在 README 事实声明登记；不与"无依据即删"冲突。
- **agent 自行推测、无依据的表述**：直接删除，推测性功能不写成已存在的事实。

"本片没有用 AI 视频生成模型"这类描述只陈述本片制作方式，是安全表述。

## 3. 叙事结构（5 幕可缩放）

1. **问题引入**（前 5 秒必须建立钩子：问句/冲突/反差，不放口号）；
2. 方案登场（是什么 + 一句话本质）；
3. 机制拆解（怎么工作，配可视化）；
4. 能力演示（可复用组件/真实输出对照）；
5. 收束宣言（价值三关键词 + 项目地址）。

短片（≤30s）可压缩为：钩子 → 机制一处 → 演示一处 → 收束。

## 4. 分镜：时间闭合与动画时刻

- 每场景列：起止时间/时长/画面/文字/动画描述（含起止时刻）/音频需求/转场/实现方式/验收标准。
- **硬校验：各场景时长之和 = 总时长**；场景内最后一个动画 ≤ 场景时长 − 0.4s（给转场淡出留缓冲）。
- 场景数 8–12（90s 量级）；每个场景独立成嵌套合成，可单独渲染检查。
- 转场统一为各合成自身时间轴内的首 0.4s 淡入 + 末 0.4s 淡出（主合成保持最小时间线），
  主合成背景深色，淡变即"through black"，无需额外转场库。
- 开场场景例外：**不要从全黑淡入**——首帧就是社交封面，必须有内容（标题暗态可见即可）。

## 5. 视觉系统：规则与反面清单

建立 design_system.md 并跨场景复用，不逐场景发明样式：

- **色板**：深色底（如 #0A0E14）+ 高对比主文字 + 单一主强调色 + 次强调色；
  声明对比度要求（正文 ≥12:1，字幕 ≥10:1，次级色仅用于大字号）。
- **字体**：显示体与代码体分开（如 微软雅黑 + Consolas）；字号分级 ≥5 档；中文行高 1.4–1.5。
- **安全区**：左右 ≥120px、上下 ≥90px（1080p）；字幕带固定底部，最长条要预演不越界。
- **组件复用**：编辑器窗、流程节点、时间轴条、字幕条、图表、印章——先在系统里定义，场景只引用。
- **动画节奏**：入场 0.4–0.6s power3.out（位移 32–48px），出场 0.3–0.4s，强调 0.2s；
  高亮用 0.2s 亮起 → 0.35s 退暗的脉冲。

反面清单（做了就会廉价或翻车）：

- 大面积无意义发光、高频闪烁、粒子海、复杂背景纹理；
- 字幕对比度不足或字号过小；
- 动画抢旁白的注意力（画面是释义不是伴奏）；
- 渲染路径上的 3D/着色器炫技——可靠性优先于复杂度，难实现的效果换成简单稳定的替代。

## 6. 场景与旁白的对位纪律

- 场景内文字**不要与字幕同文同屏**（观感重复）；大字承担的画面信息，对应字幕画面内隐藏
  （SRT 保留完整版）。
- 全片最快的一句旁白，其场景让动画提前 0.5s 起，避免"话等画"。
- 每个场景写一句"验收标准"（第 N 秒能看到什么），渲染后按此逐条核对。
