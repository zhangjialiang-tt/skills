# 质量检查方法（check 门禁 · 抽帧目检 · QC 采样）

> 出处：hyperframes-agent-video 项目实战（2026-10-30）。工具会演进，规则以当版本实测为准。

## 1. check 门禁循环（渲染前）

`npm run check` = lint + 浏览器运行时 + 布局 + 动效 + 对比度，四层全 0 错误 0 警告才算过。
逐条修复模式见 `hf-contracts.md` §8。经验值：首轮通常 8–15 条，3–4 轮收敛；
每轮只修被指名的问题，不做顺手的无关重构。

**注意**：check 通过 ≠ 好看。布局/动效检查抓不住"看起来廉价"和"信息重复"。

## 2. 快照目检循环

```bash
npx hyperframes snapshot --at 0.5,3,10,20,...   # 每场景至少 1 帧 + 首帧 + 末帧
```

逐张核对清单：

- 场景是否按 storyboard 的时间与内容出现；
- 文字截断、换行破版、越界、与场景大字同文同屏；
- 组件对齐、配色与设计系统一致；
- 打字机/逐项点亮类动画的**中间态**是否自然（光标位置、已现/未现比例）。

发现的问题分两类：结构性（回场景文件修）与节奏类（改时刻参数）。修完必须再 check 再抽帧。

## 3. 成片 QC 采样（scripts/qc_sample.py 一键完成）

```bash
python <skill>/scripts/qc_sample.py output/final.mp4 \
  --frames 0.5,3,20,60,89 \
  --speech-windows "1.0:0.5,8.0:0.5" \
  --gap-windows "6.7:0.4" \
  --expect-duration 90 \
  --outdir reports/frames
```

退出码即门禁：`0`=无异常；`2`=用法/环境错误；`3`=采样失败（请求的证据未取到，
如抽帧 0 成功、ffmpeg 子进程失败）；`4`=发现异常待人工定性。`--json` 时 stdout 只输出
纯 JSON（报告走 stderr），可被 `json.loads()` 直接解析——失败不再静默返回 0。
工具级单测：`python <skill>/scripts/qc_sample_test.py`（ffmpeg 合成视频，不需渲染管线）。

输出四块证据：

1. **ffprobe 参数核验**：codec/分辨率/帧率/时长/音轨；`--expect-duration` 按 ±0.1s
   自动比对，不符记异常（退出码 4）。
2. **关键帧抽取**：`--frames` 指定时刻，落 `--outdir`，逐张目检；有帧未取到记采样失败（退出码 3）。
3. **音量窗口采样**：speech 窗口 mean 应 -25~0dB（有声），gap 窗口 mean 应 ≤-60dB（接近数字静音 -91dB）；
   两类窗口读数颠倒即为音画错位。gap 阈值**仅适用于无背景音乐版本**。max_volume 一并输出，
   ≥0dB 记削波嫌疑（对照 audio-captions.md 判据：max≈-3dB 无削波）；无音轨视频自动跳过并登记
   `skipped_no_audio_track`，不误报异常。窗口 mean 读数只证明"指定窗口有声/近静音"，
   **音画同步需试听 + 画面对照确认，不能由 mean 推定**。
4. **blackdetect**：`d=1.0` 报出的每一段都要**抽帧定性**，不能直接当缺陷：
   - 深色主题（背景亮度 <10%）+ 文字占比小的帧会触发 98% 暗像素阈值 → 常见误报；
   - 场景转场节拍（前场淡出、后场未入）若是刻意的呼吸空拍且与旁白停顿对齐 → 合法；
   - 真缺陷（内容丢失/渲染空洞）抽帧可见大片无内容区域。

## 4. quality_report.md 结构

文件检查（逐项期望 vs 实测）→ 视觉检查（抽帧清单 + blackdetect 定性表，每段给证据帧路径）→
内容检查（事实核查引用、旁白画面对位、时间闭合复核）→ 音频检查（可播放/同步采样读数/削波/响度）→
遗留已知项（非缺陷，注明原因）。

## 5. 验证深度口径（汇报纪律）

- 静态检查 ≠ 修复；编译/检查通过 ≠ 功能验证；抽帧目检 ≠ 全片逐帧。
- 报告里写明实际做到的层级与未覆盖范围，不用低层验证暗示高层结论。
