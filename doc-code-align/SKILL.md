# 文档-代码对齐清理（doc-code-align）

对技术文档执行「以代码为唯一事实源」的清理：删除历史口径与冗余描述，改写与代码不符之处，
产出**准确且唯一表达当前系统设计**的契约文档。文档是过去时点的快照；裁定唯一依据是当前代码
与实测试结果。默认核对后直接修改，交付逐条裁定清单。

## 核心纪律（违反一条，全篇裁定不可信）

1. **禁止凭记忆写任何协议/接口事实**。FSM 状态名、位段、常量值、握手时序、字节序方向、
   数组深度，必须抄自当前代码并附 `file:line` 锚点。记忆和上游规范只用于发现疑问，不用于回答。
2. **禁止凭搜索 snippet 裁定**。命中行必须连同上下文读过（调用点、消费点、参数传递），
   确认语义后才裁定。搜索结果只是定位手段。
3. **清理 ≠ 简化**。删的是历史口径与不一致描述，不是设计细节：仍在生效的常量推导、
   时序约束、边界条件、设计选择理由必须保留。

常见借口与驳回：

| 借口 | 驳回 |
|---|---|
| "这个常量我记得是 0xA7C6" | 记忆不算证据，读定义处 `file:line` |
| "搜索已经命中，语义肯定一致" | 命名相近 ≠ 语义一致，读消费点确认 |
| "只删了几行，不用记录裁定" | 每条删除都是信息损失，必须留痕 |
| "文档写得比代码清楚，按文档保留" | 事实源是代码；文档更清楚也须先证明与代码一致 |

## 五阶段工作流

### 1. 通读建档

完整读目标文档（大文件分段读完，不留跳段），产出两张清单：

- **事实清单 F1..Fn**：全部可核事实条目——端口/参数/常量/FSM/握手/地址映射/位段/时序/
  几何/流程/依赖版本。
- **历史口径清单 H1..Hm**：按下述分类学逐条标记。

### 2. 逐条核对

对每条 F，定位实现（grep/语义搜索），读上下文，裁定：

| 裁定 | 条件 | 动作 |
|---|---|---|
| ✅ 保留 | 代码与文档一致 | 记录锚点 |
| ✏️ 改写 | 代码与文档不一致 | 以代码为准改写；记录（文档原句 → 代码事实 + 锚点） |
| ❌ 删除 | 代码中无对应实现 | 删除；记录理由（防误删未观察到路径：先确认无消费点） |
| ➕ 补缺 | 代码契约存在、文档缺失，且在文档声明范围内 | 补齐；记录锚点与推导 |

- 补缺止于文档声明的契约范围；不越界扩写成完整模块手册。
- 代码已实现但未经仿真/板测验证的行为：正文按实现描述，并标注「已实现，验证状态：未验证」；
  禁止把未验证写成已验证。

对每条 H，判定类型后**删除或吸收**进正文现在时描述（见分类学）。

### 3. 重写

- 全文统一现在时契约口吻；清除「将实现」「当前状态」「变更记录」等时态混杂。
- 历史变更点有行为含义的（如握手语义、字节序），吸收为一句话正文事实；纯过程性的直接删。
- 结构：契约优先（接口表/状态定义/流程），实现注记随后，理由性说明最后。
- 仓库内多文档互相引用同一事实（AGENTS.md / README / 寄存器表）时，逐处统一到代码口径；
  只改本次目标文档时，对他处矛盾只记录不越界修改。

### 4. 发布前校验

跑 `references/checklist.md` 全部条目，逐项留痕。硬性项：

- markdown lint：表格内竖线转义（含反引号代码段内的 `|`，用 `\|`）
- `git diff --check` 干净
- 被删标识符全文 grep 零残留
- 文档内交叉引用的文件/模块存在

### 5. 交付裁定清单

REQUIRED 输出形状——两张表 + 统计，不允许省略：

```markdown
## 裁定清单

### 事实核对（F）
| # | 文档位置 | 裁定 | 代码锚点 | 改动摘要 |

### 历史口径清理（H）
| # | 文档位置 | 类型 | 处理 | 改动摘要 |

### 统计
保留 n / 改写 n / 删除 n / 补缺 n；未验证项：…
```

报告语言与项目文档一致（默认中文）；锚点格式 `path:line`。

## 历史口径分类学（一律删除或吸收）

| 类型 | 特征 | 处理 |
|---|---|---|
| 变更日志 | 「自 change X 起」「v2.3 改为」 | 删除；行为含义并入正文 |
| 过时注记 | 「待实现」「计划支持」（实际已落地） | 删注记，正文按已实现描述 |
| 进度流水 | 「S1 完成，S2 进行中」「Phase 门禁」 | 删除；属进度管理非契约 |
| 实测记录 | 「2026-10-30 板测 22.0 s 恢复」 | 删除；测试证据归测试报告/日志 |
| 双口径并存 | 新旧两种描述同存 | 只留与代码一致的 |
| 冗余复述 | 同一契约在文内多处重复 | 收敛到唯一权威小节，他处引用 |

## 停止与升级条件

- 冻结契约文档（文档自声明 frozen / 接口冻结）或删除幅度 >30%：先出裁定清单，
  用户确认后再改。
- 代码行为存在多种解释且影响外部语义：标注开放问题，不擅自裁定。
- 无法定位实现的可核事实：标 `TBD(未核实)` 保留原文，不静默删除。
