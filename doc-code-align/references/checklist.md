# 发布前校验清单（doc-code-align）

阶段 4 逐项执行，每项留痕（通过 / 修复于何行）。前 6 项为硬性项，任一未过不得交付。

## 硬性项

1. **markdown lint**：表格内 `|` 全部转义为 `\|`（反引号代码段内同样算数——渲染器先拆表格后看代码）；
   检查命令：`grep -n '`[^`]*|[^`]*`' <doc>` 粗筛后逐表人工确认。
2. **`git diff --check`**：无 blank-at-eol / blank-at-eof。
3. **删除符号零残留**：本次删除的每个标识符/状态名/常量名，全文 grep 无残留
   （含目录表格、mermaid 图、脚注）。
4. **交叉引用存在性**：文档内引用的每个 `path`、模块名、文件名在仓库中存在。
5. **事实锚点抽样复验**：随机抽 3 条「保留」裁定，重读锚点行确认语义与文档一致
   （防裁定阶段抄错行号）。
6. **时态一致性**：全文无「将实现 / 目前 / 暂未 / 变更记录 / Changelog」字样；
   `grep -nE '将实现|以后|版本历史|Changelog|变更记录' <doc>` 应零命中（项目专名除外）。

## 一致性项（本次实战踩坑，逐条自查）

7. **FSM 状态名**：状态名抄自 RTL enum 定义处，不凭文档旧称或记忆
   （坑：文档写 `S0/S1/S2`，RTL 实际 `M_IDLE/M_RUN/M_DONE`）。
8. **「待实现」注记**：每条注记都当作疑点核查实现状态——注记常落后于代码
   （坑：`abort_req/job_seq` 握手已落地，文档仍标「待实现」）。
9. **数值注记**：深度/宽度/延迟数值以代码为准；「≥N」型契约与实现值分开写
   （坑：契约写 ≥8，实现是 16，文档混写成 8）。
10. **字节序/移位方向**：从实际数据通路推导，不凭直觉
    （坑：`{px,old}` 移位寄存器 = 新进高位的低字节在低地址）。
11. **常量三态**：有定义有消费→保留；有定义无消费→标注「无消费点」或删；
    文档有代码无→删（坑：`DESC_STALL_WARN_CYCLES` 有定义无消费，文档当活性契约引用）。
12. **mermaid/ASCII 图与代码一致性**：状态图状态名、迁移条件逐一对照 RTL FSM。

## 收尾项

13. **统计与未验证项**：裁定清单含四类计数；「已实现未验证」条目显式标注，
    不写成已验证。
14. **越界记录**：对他处文档发现的矛盾（本次不改的），在交付说明中列出，不静默。
