### B. 规划元数据与引用模型

#### B1. PlanningArtifactMeta（产物自身标识，不含 content_hash）

```yaml
planning_artifact_meta:
  schema_id: novel-master/arc-plan
  schema_version: "1.3.0"
  artifact_type: STORY_ENGINE | PROJECT_SPINE | VOLUME_ARC | ARC_PLAN | CHAPTER_BATCH
  artifact_id: string
  revision: string
  lifecycle_status: DRAFT | APPROVED | ACTIVE | SUPERSEDED | COMPLETED | DEPRECATED
```

#### B2. PlanRef（外部引用，含 content_hash）

```yaml
plan_ref:
  artifact_type: STORY_ENGINE | PROJECT_SPINE | VOLUME_ARC |
                 ARC_PLAN | CHAPTER_BATCH
  artifact_id: string
  path: string
  revision: string
  content_hash: string
```

#### B3. ItemRef（引用产物内部嵌套项）

```yaml
item_ref:
  item_type: PHASE | MILESTONE | ARC_BEAT | BATCH_SLOT | PAYOFF
  item_id: string
  json_pointer: string       # 定位缓存，item_id 是规范身份
```

**引用规则**（所有嵌套对象必须含显式 ID）：

| 引用字段 | artifact_type | item_type |
| --- | --- | --- |
| `phase_ref` | PROJECT_SPINE | PHASE |
| `milestone_ref` | PROJECT_SPINE | MILESTONE |
| `beat_ref` | ARC_PLAN | ARC_BEAT |
| `payoff_ref` | ARC_PLAN | PAYOFF |
| `batch_slot_ref` | CHAPTER_BATCH | BATCH_SLOT |

`batch_slot_ref` 的 PlanRef 部分必须与 `batch_ref` 指向同一 `artifact_id/revision/content_hash`。

**ItemRef 解析规则**：
- `item_id` 是规范身份（不可变）
- `json_pointer` 是定位缓存
- 校验：先按 `item_id` 查找 → ID 存在则 Pointer 变化不判定失效（更新缓存即可）→ ID 不存在才返回 `ITEM_NOT_FOUND` 或 `STALE_PLAN_REF`

### C. 规划产物生命周期

```text
DRAFT ──(用户或approved_workflow)──→ APPROVED
APPROVED ──(novel-master，同 Scope 无另一 ACTIVE)──→ ACTIVE
ACTIVE ──(新 revision 激活)──→ SUPERSEDED
ACTIVE ──(exit criteria 满足)──→ COMPLETED
ACTIVE/APPROVED/DRAFT ──(用户确认)──→ DEPRECATED
```

**引用规则**：
- STANDARD/STRICT：只引用 ACTIVE
- FAST：可引用 APPROVED（有警告）
- DRAFT：不可被正式引用
- 同一项目一个 ACTIVE PROJECT_SPINE；同一卷一个 ACTIVE VOLUME_ARC；同一 Arc 一个 ACTIVE Batch

**原子激活协议**：

```yaml
planning_activation_change:
  activation_id: string
  artifact_id: string
  previous_active_ref: PlanRef | null
  new_active_ref: PlanRef
  base_revisions: object
  status: PREPARED | VALIDATED | COMMITTED | ROLLED_BACK | FAILED
```

由 novel-master 原子执行：校验 ApprovalRef → 验证同 Scope 唯一性 → 旧版标记 SUPERSEDED → 新版标记 ACTIVE → 更新索引 → 更新 workflow 日志。

---

### D. 过期规则：区分未来计划和历史证据

| 章节/计划状态 | 上游规划更新后 |
| --- | --- |
| PLANNED 章节卡 | 标记 STALE，要求重规划 |
| DRAFT 正文对应的章节卡 | 标记 STALE，禁止直接接受 |
| REVIEWED 正文 | 标记 STALE，重新评审或确认 |
| ACCEPTED/PUBLISHED 章节 | **保留历史 PlanRef，不标记 STALE** |
| 已完成 Batch Slot | 保留历史映射 |
| 未执行 Batch Slot | 新 Batch revision 可替换 |

已接受章节是在当时有效规划下执行的历史证据，不能因后来改大纲而判定"引用错误"。仅高风险 Retcon 时通过 IMPACT_ANALYSIS 处理。

### E. 哈希策略

```yaml
hash_policy:
  algorithm: SHA-256
  encoding: UTF-8
  line_endings: LF
  source: canonical_payload        # 解析 YAML → 去除非语义字段 → 键排序 → 规范 JSON → SHA-256
  excluded_fields:
    - generated_at
    - display_metadata
```

对结构化 YAML Payload 规范化后计算，非语义排版变化不使引用失效。

### H. Writer 新增：`planning_execution`

| 模式 | 要求 |
| --- | --- |
| FAST 正式章节 | 必须输出最小版（beat_execution + actual_deviations） |
| STANDARD | 必须输出完整版 |
| STRICT | 完整版 + 调用 PLAN_ALIGNMENT |
| ADVISORY | 可选 |

```yaml
planning_execution:
  beat_execution:
    - beat_ref: PlanRef
      status: COMPLETED | ADVANCED | NOT_REACHED | DEVIATED
  milestone_effects:
    - milestone_ref: PlanRef
      status_change: NONE | ADVANCED | COMPLETED
  payoff_consumption:
    - payoff_ref: PlanRef
      consumption: NONE | PARTIAL | FULL | PREMATURE
  actual_deviations:
    - deviation_id: string
      planned: string
      actual: string
      proposed_level: LOCAL | TACTICAL | STRATEGIC
      evidence_ref: object
```

FAST 最小版至少含 beat_execution 和 actual_deviations。Writer 报告 TACTICAL/STRATEGIC 偏差时，即使 FAST 也升级到 Reviewer 或检查点流程。
