# ZCode 闲时任务合同

## Required fields

| 字段 | 要求 |
| --- | --- |
| `title` | 具体、可识别，≥8 字符，避免"帮我看看""全面检查" |
| `workspace` | 真实项目目录绝对路径，不使用猜测路径 |
| `objective` | 一个主要目标，避免多个无关目标混在一起 |
| `scope` | 非空字符串列表，明确目录、模块、文档或测试范围 |
| `deliverables` | 非空字符串列表，明确报告、补丁或测试产物 |
| `constraints` | 非空字符串列表，包含文件修改、Git、外部传输和工具限制 |
| `acceptance` | 非空字符串列表，可检查的完成条件 |
| `stop_conditions` | 非空字符串列表，越界、缺依赖或风险时的停止规则 |
| `execution.permission` | `read_only` / `modify_files` / `modify_and_commit` |
| `execution.model` | 可选，用户指定值或留空 |
| `execution.reasoning` | 可选，用户指定值或留空 |

## Task type policy

### `read_only`（默认）

只读检查并输出报告，不修改文件、不提交 Git。约束中必须包含"不修改"或"只读"声明。

### `modify_files`

- 用户明确要求修改时使用。
- 必须列出允许修改的文件集合和回滚边界。
- 约束中必须包含"只修改以下文件集合"的声明。
- 不修改与任务无关的文件、golden、checker 或测试严格度。

### `modify_and_commit`

- 默认禁止，必须单独取得用户确认。
- 任务指令要限定提交范围（仅本次修改的文件）、提交条件和提交信息格式。
- 不 push、不 reset、不改写历史。
- 提交前必须确认所有验证通过。

## Good acceptance criteria

- 每个高优先级结论有当前文件路径和行号证据。
- 静态检查、仿真、综合和硬件验证分开报告。
- 真实执行的命令和结果可复核。
- 未运行的工具链明确标记为未验证。
- 没有修改用户未授权的文件。

## Bad task patterns

- "全面优化项目，发现问题就修。"（无范围、无边界）
- "把所有 TODO 都处理掉。"（无优先级、无范围）
- "运行所有测试并保证通过。"（无测试范围和环境边界）
- "参考历史报告完成审查。"（无当前代码证据）

## Quality checklist

提交前检查：

- [ ] 明确写出这是 ZCode 闲时任务
- [ ] 没有误用 Codex 后台任务或子 Agent 表述
- [ ] workspace 是当前真实项目路径
- [ ] 目标、范围和交付物具体
- [ ] 有权限边界和停止条件
- [ ] 有可验证的验收标准
- [ ] 未把截图占位文字当作任务指令
- [ ] 已向用户展示完整预览
- [ ] 高风险最终动作已获得确认
