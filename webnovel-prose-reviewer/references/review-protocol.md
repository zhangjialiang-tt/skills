# 文本可信度评审执行协议

本协议是 `webnovel-prose-reviewer` 的完整执行算法。SKILL.md 只给流程摘要，本文件给出每一步的判定规则。评审者按阶段 A→G 顺序执行，不得跳步。

---

## 阶段 A · 全章建模

在细读前建立本章的工作索引，避免"只见树木不见森林"。**这是内部索引，默认不向用户输出**；用户问"你怎么判断的"才展开相关部分。

### 必需项（每次都建立对应字段）

| 字段 | 含义 | 字段值状态 |
|---|---|---|
| 场景划分 | 本章场景边界 | 已确认 / 正文推断 / 未提供 / 不适用 |
| 视角人物 | 谁的视角 | 同上 |
| 当前目标 | 视角人物此刻要做什么 | 同上 |
| 关键信息状态 | 角色知道什么、不知道什么 | 同上 |
| 关键事件或转折 | 本章发生了什么不可逆的事 | 同上 |
| 已冻结人设锁 | book_rules 定义的性格/行为硬约束 | 同上 |
| 本章计划关键落点 | 章节计划要求本章实现什么 | 同上 |

**字段值四态**（禁止为填满字段而补写事实）：
- `已确认`：正文或设定文件明确给出。
- `正文推断`：正文未直说但可合理推出。
- `未提供`：用户没给，无法推断。
- `不适用`：本章无此维度。

### 按需项（仅在相关段落出现或风险候选需要回溯时建立）

- 人际利益关系
- 专业判断机会
- 情绪兑现机会
- 延迟反应
- 伏笔与信息释放

**按需项缺失不是缺陷**。不要求每次都对无关维度建立记录。

---

## 阶段 B · 逐段轻扫

对正文**每一段**执行轻量扫描，保证覆盖率。轻扫只判两件事：

1. **该段承担什么功能**（场景移动 / 信息交代 / 对话衔接 / 动作连接 / 节奏缓冲 / 反应 / 选择 / 发现 / 能力触发 / 异常互动 / 情绪转折）。
2. **是否含风险信号**。

### 风险信号（开放集合，非封闭枚举）

常见入口（用于提示候选，**不是封闭枚举**）：
- 人物反应
- 关键选择
- 关键发现
- 能力触发
- 异常互动
- 重要情绪
- 叙事跳转

**开放项**：任何可能影响人物可信度、因果可信度或叙事呈现可信度的异常，即使不在上表，也是风险信号。

**三路触发来源**（风险候选可由任一路触发）：
1. 局部文本异常（段落内出现上述信号）。
2. 与全章模型冲突（如信息状态矛盾、人设锁应兑现未兑现）。
3. 与作品规则冲突（人设锁、禁写项、章节计划）。

**无风险信号的段落**：标记"覆盖通过"，不深读。但仍参与阶段 D 全章模式检查（缺失型问题可能藏在"该出现而没出现"的段落里）。

---

## 阶段 C · 候选深读（四步细读）

**只对风险候选执行完整四步**。四步是内部执行程序，不是用户可见报告；用户问"你怎么判断的"才展开。

### 第一步 · 可推导反应（不是"应有反应"）

判断角色在当前处境下的反应是否可由人物状态推导出来。

**判定走推导链**（不套情绪模板）：
1. 角色当前知道什么？
2. 角色如何理解正在发生的事？
3. 这件事触碰了角色的什么欲望、恐惧、创伤或利益？
4. 性格、经验和防御机制如何过滤反应？
5. 角色如何压制、延迟或外化反应？
6. 正文反应是否与这条推导链一致？

**候选反应库**（降级为候选提示，不是判据；用于提出假设，不用于直接下结论）：
- 重生睁眼、金手指降临、发现关键线索、生死瞬间、重大损失、重逢、背叛等情境，常有对应情绪谱。
- 这些类型经验只能用来提出候选反应，不能直接作为判定标准。

**反例提醒**（不得仅因未表现常见情绪就判定断裂）：
- 多次重生者未必再次震惊。
- 解离型人物生死瞬间可能感到麻木。
- 已预期系统出现的人无需表现不可置信。
- 训练有素者可能先执行程序，之后才出现延迟反应。

**裁决**：人物推导与类型经验冲突时，**以人物推导为准**。

### 第二步 · 查人设锁

动作/判断是否符合人设锁？专业身份是通过判断体现的，还是只挂头衔？

- 对照 book_rules 人设锁（性格约束、行为约束）逐项核对。
- 强迫症→该反复核对的地方核对了吗？谨慎者→该先验证的地方验证了吗？社恐→该回避的接触回避了吗？
- 专业身份（结构师/医生/军人）→遇到专业相关情况，是给出了专业判断，还是表现得像外行？
- 对配角也用这一步：配角面对异常，反应符合其身份和利益吗？有自己的算盘吗？

### 第三步 · 查因果链

关键选择/发现/能力是怎么来的？倒推动机+信息+判断三要素是否齐备？

- 关键选择倒推：动机（想要什么）+ 信息（凭什么知道该这么做）+ 判断（怎么推出该这么做）。三者是诊断维度，聚类时不得丢失。
- 关键发现倒推：线索来源是系统提示、专业判断、还是前期铺垫？还是主角凭空察觉/系统该提示却沉默？
- 能力/金手指倒推：触发条件是什么？来源是什么？

### 第四步 · 辨展现与告知（区分有效概括与关键过程缺失）

**进入条件**：只有当直接叙述**跳过读者必须经历的心理、决策或因果过程**，并因此损害可信度、情绪重量或理解时，才标记为告知式断裂。

**四类有效概括（显式放行，不判为断裂）**：
1. 非关键状态的简洁告知。
2. 前文已经充分展现后的总结。
3. 为控制节奏使用的概括。
4. 与叙事距离一致的直接叙述。

**候选触发**（仅发现手段，不作定罪）：扫描告知式句式（"他决定X""他感到X""他没有X，也没有Y"）。命中后用进入条件判断——若属于四类有效概括，放行；若跳过了关键过程，标记。

## 阶段 D · 全章模式检查（机会—兑现协议）

**不可省**。这一层检查"该出现而没出现"的缺失型问题，是逐段轻扫无法覆盖的。

协议要求：**先识别机会，再检查是否兑现**。不列问题类型清单。

### 四类机会—兑现

| 类 | 第一步：识别机会 | 第二步：检查兑现 |
|---|---|---|
| 1 事件反应兑现 | 识别对当前人物的**目标、利益、恐惧、关系或自我认知**具有显著影响的事件（事件重大性按人物解释判定，不按外部类型，避免退回"重生一定要震惊"） | 在合理时间内是否出现可推导反应。优先检查当前场景；若人物防御机制、情节安排或信息释放支持延迟反应，应继续检查本章后续及可用计划，**不把场景结束自动视为未兑现** |
| 2 人设机会兑现 | 识别应触发人设或专业能力的机会点 | 该人设/专业判断是否兑现 |
| 3 关系与利益兑现 | 识别配角面对自身利益、风险、关系变化的时刻 | 配角是否独立反应（非配合主角流程） |
| 4 累积表达模式 | 识别单次不严重但重复出现的表达模式 | 累积后是否造成失真 |

### 累积型立案标准

**不按固定次数立案**。当满足以下任一影响条件时，才形成正式 finding：
- 是否覆盖多个关键场景。
- 是否成为该角色主要表达方式。
- 是否让读者无法区分不同情绪。
- 是否持续替代必要的决策和反应过程。
- 是否对全章可信度产生稳定影响。

单次不立案，仅记录；累积达到上述标准后聚为一根因。

## 阶段 E · 三关验证（状态制，非布尔制）

每个候选断裂点在进入正式报告前必须过三关。**设定材料缺失不自动排除问题**。

### 三关状态

| 关 | 状态值 | 含义 |
|---|---|---|
| 上下文验证 | `supported` / `not_contradicted` / `contradicted` / `unavailable` | 上下文是否支持 / 未反证 / 已解释或否定 / 材料缺失 |
| 设定与意图验证 | `supported` / `not_contradicted` / `contradicted` / `unavailable` | 针对人设锁/章节计划/作者意图 |
| 实际影响验证 | `confirmed` / `setup_dependent` / `none` | 影响已确认 / 影响依赖设定需条件展示 / 无实际影响 |

### 上下文验证的语义窗口（不固定段数）

- 先检查相邻上下文。
- 必要时扩大到当前场景。
- 再检查全章。
- 涉及人物信息、伏笔或信息释放时，检查可用设定和章节计划。

### 进入正式 finding 的规则

> 正文证据成立、实际影响成立（`confirmed` 或 `setup_dependent`），且可用上下文未形成反证（非 `contradicted`），即可进入正式 finding。设定材料缺失（`unavailable`）**不自动排除**，但必须标记为"依赖设定"并降低置信度。只有 `contradicted` 才直接排除。

**零阻塞是合法结果**：若整章没有通过三关的阻塞性 finding，输出零阻塞报告，不强行找问题。

## 阶段 F · 根因聚类

不要把每个局部句子都当作独立问题。按**根因**聚合，五类（情绪/人设/因果/配角/告知式）只作为 category 标签和最终统计，不作为主要聚合方式。

### 合并与拆分规则

**可聚类（满足任一）**：
- 同一缺失机制且可由同一修改动作解决。
- 一个问题是另一个问题的表现或证据。

**不得聚类**：
- 只有 category 相同但成因不同。
- 需要不同修复策略。
- 聚类不得掩盖动机缺失 / 信息缺失 / 判断跳步三者间的差异——这三者同属因果断裂 category，但根因不同。

**保留诊断维度**：动机、信息、判断是三个诊断维度，聚类时不得丢失。若三者属于**同一决策事件**且可通过**同一修复包**解决，可聚为一个根因，**在根因内部列出三个缺失子项**；若发生在不同事件、来源不同或需要不同修复策略，必须拆开。

### 强制示例

**可以聚类**（同一决策事件、同一修复包）：

主角决定立即去 19 号楼，但正文未交代他为什么优先去（动机）、凭什么确定楼还在（信息）、如何判断现在去最合适（判断）。三者属于同一决策事件，可由同一段"行动前核算与推导"修复。
聚为一根因"行动决策链不完整"，内部列三个子项。

**不得聚类**（同 category 但事件不同、修复策略不同）：

- 候选 1：重生后出门前未做现实验证（动机+信息+判断缺失，同一行动准备链，P019-P021）。
- 候选 2："前世他没见过这个东西"制造系统来源歧义（信息缺失，但属设定交代问题，非行动决策，P073）。

两者同属因果断裂 category，但事件不同、修复动作不同，必须保持两条。

## 阶段 G · 分级与报告预算

### 严重度（P0-P3）

- `P0 致命`：全文情绪平直 / 主角全程像机器人 / 人设根本性崩塌——必须返工。
- `P1 高`：关键转折点（重生/金手指/发现/生死）情绪缺失、人设自相矛盾、决策链断裂——建议发布前处理。
- `P2 中`：局部告知式写法 / 细节偏干 / 配角反应略平 / 感官调用不足——可下轮修正。
- `P3 低`：个别措辞 / 非关键细节——不拖慢生产。

### 软报告预算

- 所有 P0 必须输出。
- **独立且影响发布判断的 P1 不得因数量上限隐藏**。
- 默认输出 8-15 个根因。
- **压缩对象是重复实例与低优先级**，不是机械限制 P1 数量。
- 重复问题：详展一个代表样本 + 列其他位置，不重复解释。
