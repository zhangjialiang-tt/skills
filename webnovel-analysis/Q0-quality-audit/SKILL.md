# Q0 质量审计器

自动寻找格式错误、证据不足、跨 Skill 冲突、异常评分和疑似幻觉，并生成最小人工复核队列。只标记问题，不静默修改原始分析。

## 何时触发

- 每批 S6 后运行
- 每卷结束运行一次
- S8 之前运行全局审计

## 执行

1. 读取 `references/prompt-template.md` 获取完整 Prompt 模板
2. 读取 `../../schemas/enums.yaml` 获取枚举值
3. 按模板执行审计，输出标准信封格式

## 审计维度

| 维度 | 检查内容 |
|------|----------|
| 完整性 | S0 章节是否全部进入中央表、必填字段是否缺失 |
| Schema | 数值范围、枚举值合规、空值是否被错误填 0 |
| 证据 | 高强度结论是否有原文证据、证据是否支持结论 |
| 跨 Skill | S2 低释放但 S4 高爽点（**reverse 类除外**）、S1 无钩子但 S5 断章极高 |
| 跨章节 | 角色状态倒退、已关闭悬念重新开放 |
| 评分异常 | 大量集中同一分数、9-10 分过多、相邻巨幅跳变 |
| 商业风险 | 强钩子长期不兑现、连续爽前卡、付费点前未交付价值 |

### 跨 Skill 冲突检查规则

**"S2 低释放但 S4 高爽点"触发条件**（需同时满足）：
- S4 `payoff_present = true` 且 `payoff_strength >= 5`
- S2 `release_score <= 2`
- **S4 `payoff_nature != "reverse"`（反向释放绝对不触发此检查）**
- **S4 `payoff_nature` 字段必须存在**（若缺失，标记为数据问题 P2）

当 `payoff_nature = "reverse"` 时：
- **不标记为任何跨 Skill 冲突（既不是 P0 也不是 P1）**
- 仅在审计备注中记录"本章含反向释放事件，已排除冲突检查"
- 如反向释放强度 >= 7，标记为 P2 备注项（供人工参考）
- **绝不可将 reverse 事件标记为 P1 跨 Skill 冲突**

## 严重度分级

| 级别 | 含义 |
|------|------|
| P0 | 阻塞：主键重复、章节缺失、越界、明显幻觉、关键字段冲突 |
| P1 | 必须人工复核：极值评分、卷边界、主要爽点、角色反转 |
| P2 | 抽样复核：一般一致性问题、重复度风险 |

## 下游交接

- P0 问题 → 返回对应 Skill 重新运行
- P1 队列 → 人工抽检
- 全局审计摘要 → S8 判断配方可信度

## 禁止事项

- 静默修改任何原始分析字段
- 把"可能有误"说成"确定错误"
- 越权改写 S1-S5 的文学判断
