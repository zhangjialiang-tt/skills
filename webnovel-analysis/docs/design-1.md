# 爆款网文拆解 Skill 库设计

## 第一阶段：全景架构、中央数据表与两天落地排期

## 一、任务理解与关键难点

你的目标不是让 AI 临时分析一本书，而是建立一套可反复调用、可批量运行、可抽样校验的网文拆解 Skill 库。AI负责文本清洗、章节分析、数据汇总和规律提炼，你主要处理争议判断与最终确认。

关键难点有三项：

1. **不同 Skill 的结论容易互相冲突**：通过统一中央数据表和固定枚举值解决。
2. **长篇分批分析容易遗忘前文**：通过“批次摘要包＋角色状态表＋卷级滚动摘要”保持上下文。
3. **AI 容易把推测写成事实**：所有结论必须绑定章节证据，并设置“确定／推断／存疑”置信状态。

---

# 二、总体设计原则

## 2.1 推荐的最省事实现方式

首版采用：

- Markdown：保存 Skill Prompt、分析报告和题材公式。
- CSV/XLSX：保存章节级中央数据表。
- Excel 或 WPS：筛选、统计、条件格式热力图。
- Python：仅作为超长篇批处理和高级可视化的可选增强。

不建议首版引入数据库、复杂 Agent 平台或前后端系统。对单人创作者而言，**标准化 Prompt＋统一表格契约**更容易维护，也更容易人工纠错。

---

## 2.2 Skill 的三层架构

### 第一层：控制层

新增两个轻量控制模块，不直接承担文学分析。

| 模块              | 功能                                             | 增加理由                           |
| ----------------- | ------------------------------------------------ | ---------------------------------- |
| O0 拆解任务编排器 | 创建任务编号、记录书籍信息、决定批次、调度 S0—S9 | 避免每次手动决定先后顺序           |
| Q0 质量审计器     | 检查缺失字段、证据不足、跨批次冲突和异常评分     | 让用户只需抽检异常项，而非逐章重读 |

O0 和 Q0 不替代 S0—S9，而是负责降低重复操作和幻觉风险。

### 第二层：分析层

- S0 文本预处理
- S1 叙事结构拆解
- S2 情绪节奏打分
- S3 人物关系网
- S4 爽点工程
- S5 商业卡点

### 第三层：聚合与复用层

- S6 数据聚合
- S7 可视化
- S8 套路公式提炼
- S9 章节模板生成

# 五、中央数据表设计

## 5.1 数据表定位

中央数据表采用“**一章一行**”结构。

所有 Skill 均通过以下两个字段定位记录：

```text
task_id + chapter_id
```

任何 Skill 不得自行修改其他 Skill 的字段，只能填写自己负责的列。S6 负责合并，Q0 负责检查。

---

## 5.2 字段责任划分

| 字段域     | 负责模块     | 主要内容                         |
| ---------- | ------------ | -------------------------------- |
| 基础索引   | O0、S0       | 任务、书名、章节编号、批次、字数 |
| 结构信息   | S1           | 卷、单元、章节功能、事件、钩子   |
| 情绪节奏   | S2           | 情绪分、压力、释放、章内走势     |
| 人物关系   | S3           | POV、核心角色、关系事件、阵营    |
| 爽点工程   | S4           | 压抑等级、爽点类型、强度、间隔   |
| 商业机制   | S5           | 断章类型、追读问题、付费价值     |

## 5.4 关键字段定义

### 基础字段

| 字段               | 定义                 | 允许值示例                         |
| ------------------ | -------------------- | ---------------------------------- |

| `chapter_position` | 章节在结构中的位置   | 开篇、铺垫、升级、高潮、收束、过渡 |

| 字段                 | 定义                   | 允许值示例                                       |
| -------------------- | ---------------------- | ------------------------------------------------ |
| `chapter_function`   | 本章承担的首要叙事功能 | 建立困境、制造目标、展示能力、升级冲突、兑现承诺 |

### 情绪字段

| 字段               | 定义                     | 范围                               |
| ------------------ | ------------------------ | ---------------------------------- |
| `emotion_score`    | 本章读者综合正向满足度   | 1—10                               |
| `pressure_score`   | 本章压迫、受挫和焦虑强度 | 1—10                               |
| `release_score`    | 本章压抑被释放的程度     | 0—10                               |
| `emotion_curve`    | 章内主要情绪走势         | 低→低→高、平→压→爆、爽→危机        |

### 爽点字段

| 字段                       | 定义                     | 允许值示例                                         |
| -------------------------- | ------------------------ | -------------------------------------------------- |

| `reader_reward`            | 读者实际得到的奖励       | 优越感、正义补偿、安全感、掌控感、希望感           |

### 商业字段

| 字段                     | 定义                     | 范围或分类                             |
| ------------------------ | ------------------------ | -------------------------------------- |
| `paywall_suitability`    | 是否适合作为付费切分位置 | 低、中、高                             |
| `chapter_break_strength` | 章末继续阅读驱动力       | 1—10                                   |
| `follow_up_question`     | 读者看完最想知道的问题   | 他会如何证明身份                       |
| `information_gap`        | 读者已知与未知之间的差距 | 主角知道秘密，配角尚不知               |

### 证据与质量字段

| 字段                     | 定义                 | 规则                       |
| ------------------------ | -------------------- | -------------------------- |
| `core_evidence`          | 支持结论的原文摘要   | 禁止虚构，不建议长段复制   |
| `evidence_location`      | 证据位置             | 开头、中段、结尾或段落编号 |
| `analysis_confidence`    | 结论置信度           | 确定、推断、存疑           |
| `uncertain_items`        | 无法从文本确认的事项 | 无则填“无”                 |
| `conflict_flag`          | 是否与前批结论冲突   | 0或1                       |
| `manual_review_required` | 是否需要人工复核     | 0或1                       |

# 六、共享数据流转规范

## 6.1 每个 Skill 的最小输入包

每次调用 S1—S5，输入中必须包含：

```text
1. task_manifest
2. 当前批次标准章节文本
3. chapter_index
4. 前一批次摘要
5. 当前角色状态表
6. 当前开放悬念表
7. 中央数据表中已有字段
8. 当前 Skill 允许写入的字段列表
```

其中第一批没有前批摘要时，明确填写：

```text
previous_batch_summary: 无，这是第一批。
```

禁止直接省略，以免模型错误假设缺失内容。

---

## 6.2 单个 Skill 的标准输出封装

所有 Skill 统一返回：

```json
{
  "task_id": "BK20260731-001",
  "skill_id": "S2",
  "skill_version": "1.0",
  "batch_id": "BATCH-01",
  "records": [],
  "batch_summary": {},
  "uncertain_items": [],
  "conflicts": [],
  "manual_review_items": []
}
```

### 字段含义

- `records`：逐章分析结果。
- `batch_summary`：本批整体变化，用于下一批上下文。
- `uncertain_items`：文本无法证实的结论。
- `conflicts`：与前批记录不一致的内容。
- `manual_review_items`：需要创作者检查的少量关键事项。

# 七、批次处理策略

## 7.1 默认批次大小

推荐默认：

```text
普通章节：每批10章
单章超过5000字：每批5章
单章低于2000字：每批15章以内
卷末或大高潮：单独成批
```

选择10章作为默认值，是因为它通常能覆盖一个短叙事单元，同时不会让模型因上下文过长而丢失章级细节。

---

## 7.2 批次边界原则

批次不应只机械按章节数切分。优先级如下：

1. 保持一个完整的小事件或副本单元。
2. 不把高潮兑现章与其前置压抑章拆开。
3. 不把卷末章和下一卷开篇放在同一批。
4. 无法识别单元时，再按10章机械切分。

例如，第8—12章构成完整打脸事件，则第一批可设为1—7章，第二批设为8—12章，而不是固定1—10章。

---

## 7.3 跨批次上下文包

每批结束后生成不超过1500字的 `batch_context_pack`：

```yaml
batch_id: BATCH-01

confirmed_facts:
  - 林川重生回被开除当天
  - 原始采购账本存在异常

character_states:
  林川:
    current_goal: 保住账本并查出陷害者
    current_status: 尚未洗清嫌疑
    known_information:
```

# 八、人工抽样校验机制

你的目标是只检查约20%的关键结果，不逐章复核。

## 8.1 必检章节

以下章节自动标记为人工必检：

- 卷首和卷末；
- 首次主要爽点；
- 评分为1—2分或9—10分的极值章；
- 主要角色立场反转章；
- 付费卡点候选章；
- AI标记为“存疑”的章节；
- 同一字段被两个 Skill 判定冲突的章节。

## 8.2 普通章节抽样

其余章节每批随机抽检：

```text
10章批次抽检2章
```

建议抽取：

- 1章高评分；
- 1章普通评分。

这样可以同时检查 AI 是否夸大亮点，以及是否忽略平淡章节中的结构作用。

## 8.3 抽检只回答四个问题

1. 结论是否能在原文中找到证据？
2. 情绪分和相邻章节相比是否合理？
3. 爽点类型是否把普通进展误判为爽点？
4. 章末钩子是否真的能驱动下一章阅读？

# 十一、第一阶段冻结结论

本系统采用：

```text
O0 编排
→ S0 标准化文本
→ S1—S5 并行分析
→ S6 中央表聚合
→ Q0 异常审计
→ S7 可视化
→ S8 题材公式
→ S9 章节模板
```

核心不是让每个 Skill 写出更长的分析，而是让它们：

- 只负责一个明确问题；
- 只写入自己的字段；
- 使用统一章节编号；
- 对结论提供文本证据；
- 将不确定内容显式标记为“存疑”；
- 通过中央数据表完成串联；
- 将人工工作集中到异常和关键决策上。
