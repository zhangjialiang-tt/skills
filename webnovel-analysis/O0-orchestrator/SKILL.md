# O0 拆解任务编排器

将一本待拆解小说转化为可执行、可恢复、可审计的运行计划。不分析小说内容。

## 何时触发

- 工作流第一个模块，在 S0 之前调用
- 新建拆解任务、恢复中断任务、改变批次大小时调用

## 执行

1. 读取 `references/prompt-template.md` 获取完整 Prompt 模板
2. 按模板生成执行计划

## 执行规则

1. 仅依据输入规划，不假设不存在的章节数量或卷结构
2. 不确定的信息标记为"存疑"
3. 默认每批 10 章，单章超过 5000 字建议每批 5 章
4. S1、S2、S3、S4 可在 S0 后并行；S5 在 S1/S2/S4 后；S6 在 S1-S5 后
5. 每批完成后必须运行 Q0
6. 不设计复杂数据库，默认使用 Markdown、CSV/XLSX
7. 计划必须支持失败后从最近完成批次恢复

## 执行步骤

A. 建立 task_id、book_id 和版本号
B. 评估输入文件是否需要合并、清洗或章节识别
C. 规划批次，不虚构具体章节边界
D. 建立 Skill 依赖图
E. 建立每批输入、输出和人工抽检点
F. 给出运行状态清单
G. 给出四项最终交付物的验收条件

## 下游交接

- `task_manifest.yaml` → 所有 Skill
- `execution-plan.yaml` → 调用器或人工操作清单
- `file-manifest.yaml` → S0
- `review-policy.yaml` → Q0

## 禁止事项

- 分析小说文学内容（留给 S1-S5）
- 虚构章节数量或卷结构
- 设计复杂数据库或 Agent 平台
