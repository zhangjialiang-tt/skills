# S4 爽点工程

把"压抑积累—触发—释放—读者奖励"拆成事件级数据，并统计爽点类型、强度、间隔和重复度。

## 何时触发

- S0 后，可与 S1—S3 并行
- 若已有 S2 结果，应一并输入以提高稳定性
- S4 批次结果完成后交给 S5 判断商业卡点
- 全书完成后运行 `consolidation` 统计规律

## 执行

1. 读取 `references/prompt-template.md` 获取完整 Prompt 模板
2. 读取 `../../schemas/enums.yaml` 获取爽点类型/释放方式/读者奖励枚举
3. 按模板执行分析，输出标准信封格式

## 分类锚点速查

### 压抑等级

| 等级 | 定义 |
| ---: | ---- |
| 0 | 无明显压抑 |
| 2 | 明确受阻、被低估 |
| 4 | 长期重压、不可逆损失风险 |

### 爽点强度

| 分数 | 含义 |
| ---: | ---- |
| 0 | 无爽点 |
| 1-3 | 轻微 |
| 7-8 | 强 |
| 10 | 全书罕见峰值 |

## 判断原则

1. "主角得到信息"不一定是爽点，除非给读者带来明确奖励
2. "反派吃亏"不一定是强爽点，要看前置压抑和损失程度
3. 一章可以没有爽点
4. 同一事件可以包含多个奖励，但应指定一个主类型
5. 爽点间隔按"主要爽点"统计，轻微正反馈不重置计数

## 防幻觉铁律

- 仅依据提供文本
- 不因主角占上风就自动判定爽点
- 不虚构前置压抑
- 无法找到压抑对象或读者奖励时，降低置信度
- 后续尚未兑现的期待只能记录为"爽点承诺"，不能记录为已兑现爽点

## 下游交接

- 爽点事件 → S5 分析付费点和追读机制
- 章节爽点字段 → S6 中央表
- 类型、强度和间隔 → S7 热力图
- 卷级分布 → S8 提炼题材爽点公式
- 高表现爽点章节 → S9 示例模板

## 禁止事项

- 每章强行判定有爽点
- 把"爽点承诺"算作已兑现爽点
- 虚构前置压抑来解释爽点
