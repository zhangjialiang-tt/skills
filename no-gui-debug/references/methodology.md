# 方法论 — 多链路组合定位与「sim 全绿、板上出错」系统化

> 以 MIG DDR3 撕裂（2026-09-27/28，两轮闲时任务+多轮交互）为完整案例复盘。
> 排查总时长约两天，产出两个根因、两个修复、三级验证；过程里的每个方法论
> 要素都对应一次实际的弯路或突破。

## 0. 总路线：定性 → 分层排除 → 定位 → 修复 → 三级验证

```text
症状（上位机成像撕裂）
  → ① 抓包定性：发送侧健康？内容错位？丢包？      ← 决定后面所有方向
  → ② 内容对拍：错位的"形状"（恒定/随机、粒度）   ← 机制假设
  → ③ ILA 片内：写侧/读侧/时钟域活性              ← 二分定位
  → ④ sim 复现：把板上差异逐项搬进 TB             ← 根因实锤
  → ⑤ 修复 + 三级验证（sim 红→绿 → 板上 → 主机）  ← 闭环
```

反例警示：第一轮直觉先查了读侧 packer（写覆盖撕裂假设），方向错了半轮——
**①的"发送侧健康"判据其实早就排除了发送撕裂**，但内容错位的机制（写侧丢组
而非读侧错位）直到 ILA 写自洽检查才实锤。定性做得越足，后面少走越多。

## 1. 症状定性先行（抓包是第一证据）

- 先回答四个问题：发送帧率多少？每帧包数对吗？block_id 连续吗？异常在包级
  还是在内容级？
- MIG 案例：387.7fps / 114 包 / block_id 连续 → **发送结构健康，异常在
  payload 内容**——一刀砍掉半个搜索空间。
- 上位机显示帧率 ≠ 设备帧率（GUI 渲染节流 55-61fps 显示，设备实际 387fps）；
  帧率异常要用 tshark/capture 统计确认，不能信显示值。
- **用户口头报告的帧率也要先锚定口径**（哪个工具、哪个统计字段、什么窗口）再进
  假设空间——2026-09-28 帧频案的"293Hz"最初被当成 host 观测，双端同窗一分流
  （references/tshark-workflow.md §6）发现 host 零丢帧，293 本来就是设备发送真值，
  假设空间当场砍掉一半。

## 2. 地址示踪器（测试图案 = 免费的逻辑分析仪）

counter 类测试图案的像素值 = 帧内索引 ⇒ **任何读出的数据都在自报家门**。
派生技巧：

- payload 每包起始值 → packer 实际读偏移；包内 +1 连续段长度分布 → 错位
  粒度（全是 16px 倍数 = beat 级）。
- 同 pid 跨帧起始值：唯一值 1 个 = 确定性地址 bug；散开（如 165 种）= 竞态，
  两者的修法完全不同。
- 段间值跳到 0..15 = 帧尾混入下一帧首组（指针/翻转时序）；值差恰为 16 的
  倍数 = 丢/重复了整数个 beat。

没有 counter 图案时（真实传感器数据），先切测试图案再排查——可观测性投资
永远划算。

## 3. 三链路分工与交叉印证

| 层 | 链路 | 回答的问题 |
|---|---|---|
| 包级 | tshark/scapy | 谁发的？发的结构对吗？内容错位还是传输丢包？ |
| 内容级 | 上位机 capture 对拍 | 错位的形状（恒定/随机/粒度）？修复后对了吗？ |
| 片内拍级 | ILA | 哪一级握手/哪个地址流先错的？ |

交叉印证实例：ILA 证明写侧 (aw_addr, w_data) 逐笔自洽 + 主机对拍证明内容错位
⇒ **DDR 里的内容本身就错**（写侧问题），packer 无辜——两条独立链路各给一半
证据，合起来才钉死。

## 4. 「sim 全绿、板上出错」差异清单（逐项建复现锚）

板上与 unit sim 的每一项行为差异都是一个潜在的 bug 藏身处。MIG 案例实测
命中的与应建锚的：

| 差异项 | sim 里缺什么 | 建锚方式 | MIG 案例结果 |
|---|---|---|---|
| 从端零反压 | 写 rready 反压 | TB 写从属 + 可编程 ready 调度 | **命中 #1**（单槽竞态） |
| AR→首R 延迟 | ar_latency | 模型参数（受理后等 N 拍） | 未命中（纯延迟不充分） |
| burst 碎片化 | 页钳位/包边界拆分 | 真实几何 + 4KiB 拆分 | 已修（qoder，AR 观测面锚） |
| 真实 slave 返回行为 | rvalid 保持/分次呈上/多回一拍 | 假 MC tagged 数据 BFM | 命中 #2（但 shim sim 洗清，缺陷更深层） |
| 并发读写 | 同时流量的命令仲裁 | 并发写 BFM | 未命中（shim 四条件矩阵全绿） |
| 启动窗口 | 复位释放后通路未就绪 | 前 N 拍全反压调度 | **命中 #1 二层**（calib 门控缺失） |

原则：**每次"sim 绿板上错"都把新发现的差异项加进 sim**（作为常驻回归用例，
不是一次性脚本）——下一个类似 bug 会在 sim 里直接红。

## 5. BFM 自身的坑（假模型也会撒谎）

MIG 案例 shim sim 第一轮的"丢命令"是 **TB 自己的 bug**（响应分支多等一拍
导致 1-in-7 漏采命令），差点误判 DUT。BFM 规范：

- 每循环恰一个时钟事件：ReadOnly 采样 → 下一 RisingEdge 写输出；输出在
  ReadOnly 相位写值会直接违规报错。
- 双边沿/多触发循环 = 半速率采样 = 漏采（症状：数据/命令呈规律性缺失）。
- 采样致盲排查法：先在 BFM 里数它自己收到的事件数（如 CMDS n=46），与
  期望比对——BFM 没收到的事件不可能是 DUT 发的。
- tagged 数据（data=addr）让每一拍自证位置，定位能力远高于内容对拍。

## 6. 修复设计模式

- **解耦**：单槽聚合器 → N 深 skid 环形队列（生产者/消费者速率解耦）。
- **宁可丢帧不可腐化**：skid 溢出 ⇒ 整帧放弃 + 等帧边界重武装（对齐
  S_CLEAN"宁可停流不发错帧"哲学）；放弃的帧不发 desc、不翻 bank。
- **计数清零时机**：与 FSM 递增同拍清零必然竞争（非阻塞后者胜）——统一挪到
  确定无握手的安全时刻（帧边界）。
- **补偿 vs 根修**：缺陷在黑盒（MIG MC/ui 层 sim 不可达）时，观测面补偿
  （地址偏置 + prime/flush 字 + 窗口过滤）是合法手段——但要参数化
  （RD_LAG_COMP 默认 0，诚实内存下会人为漂移），并明确登记补偿依赖。
- **环境门控**：复位释放 ≠ 外设就绪（calib_done）——数据通路启门控等
  硬件 ready（集成方案里登记过、实现时漏掉的那条）。

## 7. 修复验证闭环（三级，缺一不可）

1. **sim 复现红**：修复前用例必须红（否则它锚不住 bug）。
2. **修复后 sim 绿 + 既有回归绿**：防止修 A 坏 B（skid 第一版就坏过启动窗口
   用例，靠回归抓住）。
3. **板上复测**：ILA 判据清零（如 AR↔R 配对 dx=0）+ 主机对拍 PASS。
4. **报告**：`.planning/<日期>-<主题>-debug.md`——结论速览/症状/排除项（带
   证据）/根因（机制+证据）/修复/验证/遗留；证据文件（CSV/pcap/frames.bin）
   留 tools/log/ 并在报告里写路径。

## 8. 工程纪律（事故换来的）

- **bit 溯源**：不只核 mtime——先确认 bit 出自哪条构建入口（平铺 `make build` 与
  打包 `make verify-ip` 同名不同物，见 ip-delivery-verify.md §1/§2），并登记
  「入口 + 工程名 + 日志标记 + sha256」。RTL 改动后必须确认 bit 重建（qoder 声称
  修复但只跑了 sim，bit 还是旧的——测的是旧硬件）。
- **IP 目录文件锁**：Vivado 与 ModelSim 并行 → MIG IP `_tmp` rename 失败；
  串行 + kill 残留进程。删 `.gen` IP 目录会丢 OOC 产物，须先
  `reset_run/launch_run mig_7series_0_synth_1`。
- **板不可达降级**：sim 能推进的部分推完，板上步骤列待验证清单——闲时任务
  尤其不能卡死等硬件。
- **两轮无新证据即停**：输出已知事实/已排除/当前假设/推荐下一步，交回用户。
