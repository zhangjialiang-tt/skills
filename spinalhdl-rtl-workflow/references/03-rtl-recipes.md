# 设计检查

## Stream / Flow

按 `valid && ready`（fire）接受事务。source 不应等待同接口 ready 才声明 valid；valid 置位而 ready 为低时，保持 valid 与 payload 直到接受。Flow 没有 ready，不能默认支持背压。
优先检查项目已有 `.m2sPipe()`、`.s2mPipe()`、`.queue()`、`.translateWith()` 用法；这些算子对延迟、存储和组合路径的影响不同，不作机械替换。确认零深度、复位期间和队列满/空行为。

## FSM

`SpinalEnum` + `switch` 和 `spinal.lib.fsm` 都可使用。复用项目风格；使用库 FSM 时确认版本 API 与 EntryPoint。
逐拍列出状态寄存器、组合输出、寄存输出以及转移生效点，测试进入/停留/退出/复位。不要把 goto 理解为立即改变当前拍全部输出。

## Mem

确定深度、地址边界、同步/异步读、读延迟、使能、写掩码与同址读写策略。结合目标器件与综合报告确认 RAM 推断；elaboration 不能证明 BRAM。
只在集成契约要求时使用标准内存 blackboxing；blackbox 仿真模型和综合实现必须一致。

## CDC

先识别两域频率、复位关系、事件是否可能丢失及数据一致性。
- 单 bit 稳态电平可使用经确认的同步器（如 BufferCC）；短脉冲需要事件握手/脉冲传递协议。
- 多 bit 数据用握手保持窗口或异步 FIFO；独立逐位同步不保证一致性。
- Gray 编码仅适用于满足变化规律与物理约束的场景，不能把任意数据转 Gray 就认为安全。
- 静态配置也需明确稳定期、更新协议与采样时刻。`crossClockDomain` 只豁免检查，必须有独立的安全论证与约束。

仿真覆盖独立时钟比、相位、背压、复位与边界；亚稳态与物理约束另需 CDC 工具/实现审查。

## 顶层与 BlackBox

以外部接口规范决定名称、宽度、方向、时钟复位极性和参数；按需 setName/noIoPrefix，不能为可读性擅改 ABI。
BlackBox 检查模型源码列表、顶层模块名、generic/parameter、端口与仿真库。仅审查本次命令生成的文件清单；旧 *.v 不作本次证据。

## 编码规范与综合质量护栏

以下约束服务于生成 RTL 的审查、调试与推断，不把通用 Scala 软件的函数式程度作为质量指标。

1. **具名节点与逻辑分组**：复杂功能块使用 `val xxxStage = new Area { ... }`，关键流水级、状态与算术中间量绑定具名 `val`；避免把需观察的整条数据通路藏进长串匿名 map/reduce。规整的 map、Vec、平衡归约仍可使用，但保留关键级的名称、位宽和延迟可追踪性。Area 是逻辑命名分组，不引入组件边界，也不保证综合后保留层次或减少硬件资源。
   循环生成通道使用可追踪的集合索引或项目命名规则；自动名称不足以定位时才用 `setName`/对应版本 `setCompositeName`，确保名称唯一并保留外部端口契约。有效 idsl plugin 有助于命名；内部 `_zz_` 或 `when_*` 名字本身不是失败判据，优化后节点也可能消失。
2. **引用与复位纪律**：遵循[语言语义](01-language-semantics.md)中的 `val` 绑定及控制/数据复位规则。审查有效性是否屏蔽全部未初始化数据，并核对目标器件的寄存器打包结果；不为统一写法给宽数据通路批量加复位。
3. **配置与端口分离**：新模块超过 3 个独立配置参数时封装为纯 Scala `case class XxxConfig(...)`；已有公共构造接口保持兼容，不借机重构。静态位宽、深度、对齐与组合限制在配置构造/使用入口用 `require(...)` 提前校验。Bundle 可接收配置用于确定结构，但软件配置不是运行时 IO 字段；实际可变控制值才定义为硬件信号。
   每个接口统一采用实现 `IMasterSlave` 的 `master`/`slave` 角色定义，或完整显式 `in`/`out`；逐项检查方向与所有权，避免一部分依靠角色、一部分遗漏方向。复合接口按子接口划分，保留项目已有且完整的方向约定。
4. **存储端口结构**：每个物理 Mem 读写端口一处定义，保持扁平可审查；优先通过该版本 API 的 `enable`、写 `mask` 表达控制，避免条件树中重复调用意外产生多端口。使用 mask 前校验写数据分组与掩码宽度。嵌套 when 本身不证明推断失败，应检查实际生成结构。
   面向推断 RAM 的同步读路径，不直接对 `readSync` 返回值添加 `.init(...)`；需要确定启动值时先按契约采用有效位屏蔽，或经目标器件模板验证的输出寄存/复位结构。该规则不等同于“所有 FPGA BRAM 输出寄存器不支持复位”；存储阵列初始化、输出复位与阵列逐项清零需分别评估。
5. **可审查的 Scala 子集**：不新增自定义 `implicit def`/`implicit class` 或用于硬件描述的宏、反射、类型类层叠；使用 Spinal/标准库已定义且项目适用的导入，不将 import 限死为两个包。复用现有项目抽象前确认其展开结果，不为风格偏好改写库 API 或移除已有隐式机制。
6. **生成物与实现证据**：核对本次 RTL 的关键具名节点、端口、寄存器复位、存储端口数与读延迟。具名和结构检查属于静态/展开验证；BRAM/DSP/SRL 使用、面积与时序须以目标工具的综合/实现报告确认，不承诺与手写 RTL 等价的 QoR。
